# W3-10 AI platform base: QA report

This report covers the AI platform base that W3-04 and W3-11…W3-13 build on (11 §1 and §5, 07 W3-10). It lists what is built, the evidence, and the open questions for the lead.

- **Branch:** `claude/gallant-colden-f8b446`, on main f033f31. One commit, not pushed.
- **Where it ran:** locally only. The DB tests used the shared test Postgres (`make testpg-up`, port 5439), and the recorded evals ran under `scripts/no-egress.sh`. No provider, cloud account or key was touched. Live evals (`make ai-eval`) were not run, because they need the user's own key.

## What was built

| Area | What |
|---|---|
| `internal/ai/client` | **LLM interface.** One `Complete` call that forces one tool call, with `strict: true`, `disable_parallel_tool_use` and no `temperature`. It returns the tool input, the usage and the model.<br>**Anthropic client.** Raw HTTP to `LLM_API_URL` + `/v1/messages`, through `httpx.NewOutboundClient`. It sends no key when the URL is the mocks. `metadata.user_id` carries only `tz:<feature>:<ref>`, never a person.<br>**Failures.** Refusal, `max_tokens`, no tool call and a different tool each become a typed error. `ProviderError` covers 429/529/5xx and `Retry-After`.<br>**Sarvam STT client.** Multipart to `STT_API_URL` + `/speech-to-text`.<br>**Metered wrapper.** A span per call, plus the counters `tz_ai_calls_total{feature,model,outcome}`, `tz_ai_tokens_total`, `tz_ai_cost_paise_total{feature,model}`, `tz_ai_rejected_total{feature,reason}` and the histogram `tz_ai_latency_seconds`.<br>**`CostPaise`.** A price table in paise per million tokens, covering long-prompt pricing and cache write/read. An unknown model is priced as the dearest. |
| `internal/ai/schema` | `Decode`: a strict tool-input decode (unknown fields, trailing data and empty input are refused), then the output's own `Validate`.<br>`Numbers` / `Ungrounded`: the number-grounding validator (11 §1 rule 5). Any number in model text that is in none of the inputs fails it. It reads Indic digits, ₹, Indian and Western comma groups, and decimals. |
| `internal/ai/scrub` | The PII scrubber (11 §1 rule 6). It removes phones (+91/0/91, spaced or dashed), emails, UPI ids, card numbers, ids (Aadhaar, PAN, GSTIN), PIN codes, OTP-like codes and the known names and address lines the caller passes, each with a typed placeholder. Quantities like "120 500" are not taken for a PIN. |
| `internal/ai/prompts` | `prompt.md` files with a `version:` front matter, registered per feature from an `embed.FS`. `Version(feature)` is the string stored on every draft (rule 9). A body change without a version bump changes the stored version (a content hash), so it can't go unnoticed. |
| `internal/ai/guard` | **Feature registry.** Each feature's flag, providers (LLM, STT or both) and subject scope.<br>**`Available`.** The feature's flag is on and its providers are set. A mock counts only in `APP_ENV=local`.<br>**`Reserve`.** The per-customer cap (`ai_daily_calls_customer`) and per-store cap (`ai_daily_calls_store`), then the platform spend cap (`ai_daily_cost_cap_paise`). A refused call gets `429 ai_daily_cap_reached` with `extensions.scope` and `Retry-After` set to the next IST midnight.<br>**`Settle`.** Adds the call's cost to today's platform row. It logs a warning once per day at 80 % and sets the `tz_ai_cost_cap_used_ratio` gauge.<br>**Cap 0.** A cap of 0 stops every call (the kill switch).<br>**`tz_ai_capped_total{feature,reason}`.** Counts refused calls.<br>All numbers come from `platform_settings`. |
| `internal/ai/drafts` | The `ai_drafts` service (D-46, rule 11).<br>**Lifecycle.** `Create` (processing), then `MarkReady` or `MarkFailed`. Both are idempotent for a retried job. `Get` is scoped to the feature and the caller's `Check`.<br>**`Confirm`.** Takes one decision per line (accepted, edited with a value, or discarded) and calls the feature's `ApplyFunc` in the same transaction, with the confirmer as actor. It stores per-line outcomes, including `not_permitted` for "Ask a manager" lines (D-06, D-65). A repeat returns the stored answer without applying again. All lines discarded closes the draft as `discarded` without calling Apply. A wrong answer from Apply rolls everything back.<br>**`tz_ai_draft_lines_total{feature,outcome}`.** Feeds dashboard 14's acceptance rate (rule 10). |
| `internal/ai/eval` + `cmd/todayz ai eval` | **Eval framework.** A `Suite` (cases, grader, pass bar) and `Run`, which reports score, cost and p95. `Replay` serves recorded model replies, so `make check` needs no network.<br>**`ai_selftest` suite.** 12 recorded cases in five languages that exercise scrub → prompt → client → schema → grounding end to end. The feature suites (W3-04, W3-11…13) register the same way.<br>**`todayz ai eval <feature\|all> [--live]`.** Exit 0 on pass, 1 below the bar, 2 on bad usage. `--live` refuses to run without the user's own `ANTHROPIC_API_KEY` and a real `LLM_API_URL`. |
| `cmd/todayz` | **`aiKitFor(d)`.** Builds the metered LLM, the guard, the drafts service and the metered STT once per process. Each feature builds its endpoints from it. The `ai` subcommand is in `main.go`.<br>**`mountAI`.** Mounts no route of its own (see open question 2). |
| Migration `31001_w3-10_ai_drafts.sql` | **`ai_drafts`.** Constraints for feature names, status, output, outcomes array, confirmed fields, failure and non-negative counts. No PII columns.<br>**`ai_usage_daily`.** The guard's counters per IST day, by scope (store, customer or platform) and subject. |
| `db/queries/ai/ai.sql` | `ReserveCall` is an atomic increment that is refused at the cap, so concurrent calls can't pass it.<br>`AddPlatformCost` / `PlatformSpend` hold the day's spend.<br>The draft queries guard their state with `WHERE status = …`. |
| api `ai` base | `schemas/ai.yaml`: `AiDraftStatus`, `AiDraftAccepted` (202), `AiLineId`, `AiLineDecision`, `AiLineOutcome`, `AiLineBlocked`, `AiConfirmRequest`/`Result` and `AiCapScope`.<br>`problems/ai.yaml`: `ai_daily_cap_reached` (429). A hidden feature and a draft that is not the caller's are the common `not_found`; confirming a processing or failed draft is the common `invalid_transition`.<br>The feature paths reference these. W3-10 has no paths of its own. |
| `infra/grafana/alerts/ai.yaml` | `tz-ai-cost-80` (warning) and `tz-ai-cost-cap-reached` (critical). Both run on Postgres (`ai_usage_daily` against `platform_settings`), which is the one total across all processes. |
| `infra/grafana/dashboards/14-ai-quality-cost.json` | "14 · AI quality and cost", 13 panels:<br>- How to read this.<br>- Spend today, cap used (thresholds at 80 % and 100 %), calls today, and calls refused in 24 h.<br>- Spend per day against the cap, and spend by feature.<br>- Calls by feature and outcome, and latency p95.<br>- Rejected outputs by reason, and calls refused by cap.<br>- Draft line outcomes by feature, and drafts by feature and status (with p95 ms).<br>No panel shows a person. |
| `docs/runbooks/ai-cost.md` | The runbook for both alerts: the checks on dashboard 14 and `ai_usage_daily`, then raise the cap, turn one feature's flag off, lower a per-subject cap, or set the cap to 0 to stop everything. |
| `mk/28-ai.mk` | **`check-ai-eval`** (in `CHECK_STEPS`). Runs `todayz ai eval all` on recorded replies, so it works under no-egress.<br>**`ai-eval-live`** (in `AI_EVAL_STEPS`). Loads `.env.local` and points `LLM_API_URL` at `AI_EVAL_LLM_API_URL` (by default the Anthropic API) with `MOCK_LLM=0`. |
| `internal/rollups/alerts_test.go` | **Another WP's file (W3-07): a one-line edit.** `ai.yaml` is added to `otherAlertFiles`, so W3-07's "exactly 11 files, 24 rules" lint skips it. W3-10's own lint and firing test is `internal/ai/guard/alerts_test.go`. |

- **Go tests.** `go test -race -count=1 ./internal/ai/... ./internal/rollups/... ./cmd/todayz/...` passes. That covers client, drafts, eval, guard, prompts, schema, scrub, rollups and cmd/todayz (cmd/todayz takes 132 s under race).
- **Lint and static checks.**
  - `gofmt -l` is clean, and so is `go vet` on the same packages.
  - `golangci-lint run ./internal/ai/... ./cmd/todayz/... ./internal/rollups/...` reports 0 issues. One `//nolint:nilerr`: in the selftest harness, a rejected output is a scored outcome, not an error.
  - `gosec` on `internal/ai` and `cmd/todayz` reports nothing.
  - `settingslint` passes. The one constant is the 30 s provider HTTP timeout, marked `//settings:ok`.

- **Contract.** `make gen-contract check-contract-lint check-contract-client` exits 0. Redocly gives 16 warnings, all "unused component". Six of them are the new `Ai*` schemas, which only the feature paths will use; the others are older.

## Open questions for the lead

1. **Status names.** 03 has draft|confirmed|discarded|failed and 04 §2.8 has processing|ready|failed. The table uses processing|ready|confirmed|discarded|failed: 03's `draft` is split in two, as 04 shows. Line outcomes are accepted|edited|discarded|not_permitted (04 and dashboard 14), not 03's confirmed|rejected. 03 needs updating, or tell me otherwise.
2. **Shared draft endpoints.** 07 calls the drafts "shared draft endpoints", while 04 §2.8 gives each feature its own (`/v1/business/voice/drafts/{id}`, `/v1/me/ai/…`). I followed 04: W3-10 serves no route, `api/paths/ai.yaml` stays `{}`, and features mount theirs from `aiKitFor(d)` and the shared schemas.
3. **Prices.** `client/price.go` is list price at ₹88/$, with a cache read approximated as 10 % of input. The rupee rate and prices are code, not `platform_settings`, because they are a cost estimate, not a product number. Say if the founder wants the rate as a setting.
4. **Speech cost.** STT calls count against the call caps, but their cost is not metered yet: the Sarvam price per second isn't in the plan. They add 0 paise to the spend cap.
5. **Haiku and thinking.** Requests send no `thinking` field: tool-forced extraction on Haiku doesn't need it, and adding it raises cost. Features that use `ai_model_smart` can decide later.
6. **A-08's `assistEnabled`.** `internal/admin/catalogue.go:348` (W3-05) checks only `ai_catalogue_enabled`. It should call `guard.Available(ctx, "catalogue")`, so that the slot also hides when the key is missing (11 §1 rule 2). This is W3-05's or W3-13's file, so I did not change it.
7. **`main.go` edit.** It adds the `ai` subcommand: one usage line and one case. It is shared with other WPs.
8. **No guard spec for `ai_selftest`.** The selftest feature exists only for the eval CLI. It is not in the guard registry, so it can't be called through the API.
9. **`<AssistSlot/>`.**
   - **Backend side.** The screen's API returns `assistEnabled` from `guard.Available`. The slot then calls the feature's endpoint and handles 202 → poll → ready/failed, and 429 `ai_daily_cap_reached` with "AI help is paused until tomorrow." and no retry. It sends the confirm with one decision per line.
   - **Frontend side.** The mounts already exist in their owners' screens: `admin/src/catalogue/AssistSlot.tsx` (W3-05) and `customer/src/search/slots.tsx` (W2-08). W3-10 added no shared `shared/ui` component.
   - **To decide.** Should one be added (for example `shared/ui/AssistSlot` with the paused state), or does each feature build its own?
10. **SDK.** The client is raw HTTP, not `anthropic-sdk-go`, because the repo's rule is one outbound client (`httpx.NewOutboundClient`, with no-egress and `*_API_URL`) and no new dependency. The request shape is checked by test.
11. **No retries.** The client never retries. Retryable errors are typed and carry `Retry-After`, so the feature's River job can retry with its own budget. A retry inside the client would double-count against the caps.
12. **Per-process gauge.** `tz_ai_cost_cap_used_ratio` is per process. The alerts and the dashboard's cap panels read Postgres instead, so they are correct across the API and the worker.
13. **W3-07's lint test edit.** This is the `otherAlertFiles` line in `internal/rollups/alerts_test.go`, listed in the table above.
14. **Live eval URL.** `infra/local/local.env` points `LLM_API_URL` at the mocks. `ai-eval-live` therefore overrides it with `AI_EVAL_LLM_API_URL` (default `https://api.anthropic.com`) and sets `MOCK_LLM=0`, but only for that step.
