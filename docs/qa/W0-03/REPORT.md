**Platform packages** (`backend/internal/platform/`)

| Package | What it does |
|---|---|
| `config` | Reads the environment only. The `Secret` type never prints. Logs names of unset variables, never values. App keys (D-18) are fatal only when deployed. |
| `clock` | `Clock` interface, UTC real clock, `Fake`, `Offset` (the test clock), IST day boundaries. |
| `ids` | ULIDs, monotonic within a millisecond, with UUID round-trip. |
| `money` | Paise as int64. Add, subtract and multiply are overflow-checked; basis points use explicit rounding; `Allocate`. |
| `db` | pgxpool open (the URL never appears in errors or logs); transactions passed through context. |
| `idempotency` | Postgres store plus middleware, scoped by principal. Replays a stored response; mismatch is 422 `idempotency_mismatch`; in flight is 409 `conflict`; a 5xx or panic releases the key. |
| `httpx` | chi router with the 12 middleware slots (order and owners in `httpx/mw/doc.go`), problem+json errors, and the outbound HTTP client behind the egress guard. |
| `httpx/problem` | Codes come from `api/problems/*.yaml`, generated by problemgen into `gen/problems`. An unregistered code becomes a 500 and is counted. A scanner test catches unregistered string literals. |
| `settings` | `platform_settings` cache with TTL plus LISTEN/NOTIFY invalidation, typed getters with unit checks, generated key constants. |
| `audit` | `audit_log` writer that joins the caller's transaction. |
| `telemetry` | slog JSON with a redaction handler (by key and by value pattern), OTel bootstrap, and Sentry with every PII collection channel off plus an event scrubber. |
| `egress` | `TODAYZ_NO_EGRESS` guard: only loopback dials are allowed, checked on the resolved IP; proxy env vars are ignored. |
| `health` | `/healthz`, `/readyz` (db, migrations, river; no error text in the response), `/version`. |
| `migrate` | goose with embedded SQL, plus River's schema as Go migration version 3. |
| `queue` | River client running as `todayz_app`; platform jobs, including the nightly `ensure_partitions`. |
| `pgnotify` | One LISTEN connection with reconnect. |
| `testclock` | `GET/POST /v1/test/clock`, local and test only (D-80). The offset is shared across processes through NOTIFY; `wait` blocks until due jobs have run. |
| `reqctx`, `buildinfo` | Request-scoped values; version info. `make backend-bin` stamps commit, commit time and dirty through ldflags. |

## SC-PL-06 (settings guard)

`08-testing.md` has no SC-PL-06 row, so I built the three checks the brief describes.

1. **Doc ↔ migration.** `TestSettingsMatchProductRules` parses 01 §17 and the seed migration and fails on any key, unit or default that is in one but not the other. `TestKeysMatchMigration` checks the generated key constants against the migration.
2. **D-19 (no secrets in settings).** `TestNoSecretSettings` checks there are no key, token or secret names. `TestSchemaRefusesSecretsAndBadValues` shows the CHECK constraint refuses them at insert.
3. **Lint with a seeded fixture.**
   - `settingslint` reads the distinctive integer defaults from the migrations: 14, 21, 72, 365, 2000, 3000, 4500, 10000, 50000.
   - It flags matching integer and float literals in `internal/`. It skips platform, devtools, testkit, seed, tests and generated files.
   - It also catches `50_000`, `0x7D0` and `4500.0`.
   - The escape is `//settings:ok <reason>`. A bare `//settings:ok` is itself a finding.
   - `TestFixture` asserts the exact 5 findings in `testdata/src/internal/orders/orders.go`: lines 8, 18, 22, 27 (no reason) and 29. The files that should be ignored produce none.
   - `TestBackendIsClean` runs the lint on the real tree, and `make check` runs it too.
