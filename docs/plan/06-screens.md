# 06 · Screens and acceptance criteria

Visuals: the design system artifact (v8) and its copy in `design/source/`. Component names below (StoreMap, KpiTile, PosCart …) are the design system cards and the `@todayz/ui` components built from them. Screen IDs (`C-xx`, `B-xx`, `A-xx`, `S-xx`) are used by work packages and test scenarios.

Every screen, in addition to its own criteria, must:

- **G1** Have loading (skeletons shaped like the content, no spinners over 300 ms), empty (icon ring + one sentence + one action), error (problem `code` translated + "Try again") and offline states.
- **G2** Use only tokens and `@todayz/ui` components; pass axe with no serious/critical issues; keyboard reachable with visible focus; touch targets ≥ 44 px on phone.
- **G3** Have all text in i18n keys; layout survives Tamil/Kannada strings 40% longer than English (tested with a pseudo-locale `en-XA`).
- **G4** Emit its RUM route and the events listed in [05-observability.md](05-observability.md).
- **G5** Work at 360×740 (small Android), 390×844 (iPhone), and for business/admin 1280×800 and 1440×900.
- **G6** Be deep-linkable (URL holds state: filters, tabs, selected item).
- **G7** Read every number in user-visible copy that [01-product-rules.md](01-product-rules.md) marks configurable from `platform_settings`, never from a constant (D-60). Numbers in the criteria below ("30 credits", "₹100 or more", "+10 min", "5 min", "15 s", "up to 3 live banners", "0–20 %", "over ₹500" …) are today's defaults.
- **G8** Every reason picker uses the enums in D-60 and D-68 (reject, delivery-failed, admin-cancel, customer-cancel, shop-cancel `ShopCancelReason`, review tags), with labels from i18n keys. No free-typed reasons where an enum exists.

Screen owners are listed in [07-work-packages.md](07-work-packages.md). Where a decision in [12-decision-log.md](12-decision-log.md) settled an owner, the row below names it.
