# ADR 0002: pgx and sqlc for data access

- Status: accepted
- Date: 2026-10-22
- Plan: docs/plan/02-architecture.md

## Context

The domain is SQL-heavy: PostGIS radius queries, double-entry ledgers and rollups. An ORM would hide the SQL we most need to tune.

## Decision

Use pgx v5 as the driver and pool, and sqlc to generate typed Go from hand-written SQL in `backend/db/queries/<domain>*.sql`. Migrations are goose SQL files that are only ever added, never edited.

## Consequences

Every query is visible and can be tuned with EXPLAIN. sqlc output is generated by `make gen` and not committed. Dynamic filters need small hand-written builders.
