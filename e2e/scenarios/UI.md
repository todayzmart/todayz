# UI kit scenarios (SC-UI)

Owner: W1-02 (`shared/ui`, `@todayz/ui`). Format as in [08-testing.md §3](../../docs/plan/08-testing.md): `ID · Given / When / Then · level` (U unit, I integration, E E2E, M manual). Here E means Chromium against the built Storybook (`make e2e`, step `e2e-ui-visual`); U runs in `make check` (step `check-ui`).

| ID | Scenario | Lv | Where |
|---|---|---|---|
| UI-01 | Given each of the 23 design system component cards (`design/source/components/<Card>/preview.html` with the tokens stylesheet), when its `DesignReference` story is rendered at the card's size, then at most 0.1% of pixels differ (pixelmatch threshold 0.1; icons are masked at the same boxes on both pages, and the map drawing on StoreMap). The five screen cards (AdminConsole, BusinessOverview, BusinessPOS, CustomerScreens, Cover) are compared by the app WPs, not here | E | `shared/ui/visual/design.spec.ts` |
| UI-02 | Given every story (156), when axe runs with WCAG 2.0/2.1/2.2 A and AA rules, then there are no violations: in happy-dom for structure and names, and in Chromium with the real tokens for colour contrast. Only the listed design-owned CartBar contrast findings are excepted, by story, rule and node | U, E | `src/test/stories.test.tsx`, `visual/a11y.spec.ts` |
| UI-03 | Given the stylesheet and every source file, when they are scanned, then there are no colour literals (hex, rgb, hsl, oklch), no dark-theme query, and every `var(--…)` is a property the tokens declare | U | `src/test/styles.test.ts` |
| UI-04 | Given any component, when it renders, then every visible or announced string comes from its props (no i18n import, no English literal in the kit apart from the `©` credit default); money, distance and time arrive pre-formatted. Checked by review and by stories using only the design previews' synthetic names | M, U | `shared/ui/CLAUDE.md` rules; stories |
| UI-05 | Given the OTP input, when a user types, pastes or autofills a code, then the boxes form a group named by the label, each box takes one digit, focus advances, non-digits are dropped, `onComplete` fires once per code (not again for the same code until it is edited or cleared), Backspace and arrows move back (also on Android keyboards, which send `beforeinput` deleteContentBackward and no Backspace key), and an error marks every box invalid and is announced | U | `src/OtpInput/OtpInput.test.tsx` |
| UI-06 | Given a product with stock, when the shopper taps Add and then + up to the stock limit, then Add turns into a stepper with focus kept on it, + stops at the limit (it stays focusable, `aria-disabled`, and the limit is announced politely), and an out-of-stock product disables Add while an item already in the cart can still be reduced | U | `src/QuantityStepper/QuantityStepper.test.tsx`, `src/ProductCard/ProductCard.test.tsx` |
| UI-07 | Given the store map with WebGL, when it loads offline, then MapLibre draws the token-coloured basemap, the radius ring, pins and clusters with no network request; while MapLibre loads, the static drawing stands in (`aria-busy`); without WebGL, or if MapLibre fails to load, the static renderer draws the same pins, clusters, ring and customer dot. WebGL is probed once per page. A cluster tap zooms in; a new radius refits the ring; pins follow a pan at most once per frame | U, E | `src/StoreMap/*.test.ts(x)`, `visual/screens.spec.ts` (full map) and the guarded Chromium runs |
| UI-08 | Given a dialog or sheet, when it opens, then it is a named modal that locks page scroll (shared across nested modals), focus moves inside (to `initialFocusRef`, else the dialog), its body mounts only once opened, and it closes on Escape and on a press that starts and ends on the backdrop (not a drag out of the content) unless it is a non-dismissible alert dialog; any native close (Escape, `form method=dialog`) is reported through `onClose`. In Chromium: Escape closes it, the parent's state follows, focus returns to the opener, and a toast raised while it is open is visible and its action clickable | U, E | `src/Dialog/Dialog.test.tsx` (Dialog and Sheet share the modal), `visual/overlays.spec.ts` |
| UI-09 | Given several toasts, when more than `max` (default 3) are shown, then the oldest leaves first; each hides after its duration (default 4 s; 10 s for a toast with an action), all pause while the region is hovered or holds focus, they live in a polite live region, and while a modal is open the region moves into it so it stays above and clickable | U | `src/Toast/Toast.test.tsx` |
| UI-10 | Given a data table, when a sortable header is clicked, then rows sort ascending, descending, then unsorted (numbers descending first), `aria-sort` follows, controlled sorting reports changes, loading shows skeleton rows with `aria-busy`, and an empty table shows one full-width message cell | U | `src/DataTable/DataTable.test.tsx` |
