# Field agent scenarios (SC-FA)

FA-01…FA-10 belong to W3-06 (`admin/src/field`, `backend/internal/business/agent*.go`, api `admin-field`). They are builder-written, with at least one scenario per A-04 and A-15 acceptance criterion in [06-screens.md](../../docs/plan/06-screens.md) and per field rule in [01-product-rules.md](../../docs/plan/01-product-rules.md) (D-39, D-47, D-64). The format follows 08 §3: `ID · Given / When / Then · level`, where U is unit, I is integration, E is E2E and M is manual. Go tests are in `backend/cmd/todayz/field_http_test.go`, admin unit tests in `admin/src/field/field.test.tsx`, and Playwright journeys in `admin/e2e/field.spec.ts` (360 px phone).

| ID | Scenario | Lv | Where |
|---|---|---|---|
| FA-01 | Given a field agent, when they start a shop with a name and the owner's number, then the business is a draft with `onboarded_by` set to the agent, it is not confirmed, and the request carried an Idempotency-Key. A number that is not a 10-digit Indian mobile is refused on the phone before any call. The agent's own number is refused by the API (422 `body.ownerPhone`). | I, U, E | `TestFieldOnboardingHTTP`; `field.test.tsx` "checks the owner number before creating"; `field.spec.ts` A-04 |
| FA-02 | Given a shop with no category or no complete store, when the agent asks for the owner's code, then the API answers 409 `submit_incomplete` with the missing fields and sends no SMS, and the wizard sends the agent to the step that fixes it | I, U, E | `TestFieldOnboardingHTTP`; `field.test.tsx` "Finish the store"; `field.spec.ts` A-04 ("Add the category") |
| FA-03 | Given a ready shop, when the code is sent, then the owner's number is shown masked, the expiry is shown, and resending waits out `resendAfterSeconds`. When the owner reads out a wrong code, then the agent sees how many tries are left. When they read out the right code, then the business is `submitted`, `ownerConfirmed` is true, and the owner can see it in the business app. | I, U, E | `TestFieldOnboardingHTTP`; `field.test.tsx` "sends the owner a code"; `field.spec.ts` A-04 |
| FA-04 | Given a shop's store inside the edit window, when the agent searches the catalogue and adds a master product with a price and opening stock, or adds a new product, then it is listed in the store. A new product is `pending_review` (D-64), and a product already in the store is 409 and shown as "Already listed". (Price above the MRP: the catalogue rule refuses it as `validation_failed`, and the wizard words it; no W3-06 test covers it.) | I, U, E | `TestFieldOnboardingHTTP`; `field.test.tsx` "adds from search"; `field.spec.ts` A-04 |
| FA-05 | Given the photos step, when the agent takes a storefront or inside photo, then the API registers it and answers a presigned PUT, the file goes straight to object storage (never through the API), and only shop_photo and storefront are accepted, at most 5 of each. A non-image file or one over 10 MB is refused on the phone before any call. | I, U, E | `TestFieldOnboardingHTTP`; `field.test.tsx` "uploads a photo", "refuses a large photo"; `field.spec.ts` A-04 |
| FA-06 | Given a sent code, when five wrong codes are read out, then the sixth try is 429 `otp_locked`. A code older than 5 minutes is 401 `otp_expired`. A new owner number ends the old code. | I | `TestFieldOwnerCodeLimitsHTTP` |
| FA-07 | Given a business another agent onboarded, when an agent reads or changes it, then every field route answers 403 and their list does not show it. A business the shop created itself is not on the field routes (404). | I | `TestFieldEditWindowHTTP` |
| FA-08 | Given a business verified 29 days 23 hours ago, when its agent adds or edits an item, then it is allowed. At 30 days and one second, writes are refused, the list still reads, and the wizard shows the shop read-only. Raising `field_agent_edit_window_days` (a setting, not a constant) lets the agent back in. An admin is not windowed (D-39). | I, U | `TestFieldEditWindowHTTP`; `field.test.tsx` "closed window is read-only" |
| FA-09 | Given a field agent with onboarded, verified and live shops and items added, when they open A-15, then they see only their own numbers (onboarded, verified, live, products added, in window, first-order rate) and an 8-week trend, from `/v1/admin/field/me/stats`, and the page never calls `/v1/admin/field-agents` | I, U, E | `TestFieldStatsHTTP`; `field.test.tsx` A-15; `field.spec.ts` "A-15: a field agent" |
| FA-10 | Given an admin, when they open A-15, then they see every agent in a table and pick whose weekly trend to show. A field agent who calls `/v1/admin/field-agents` gets 403. The sidebar shows Add shops and Field agents to field agents and admins only (AD-02). | I, U, E | `TestFieldStatsHTTP`; `field.test.tsx` A-15; `field.spec.ts` "A-15: an admin"; `roles.spec.ts` |

Audit (part of FA-01…05): every field write is audited with the agent as an admin actor, and no audit row, log line or response carries the owner's full number or a code (`TestFieldOnboardingHTTP`, "Audit"). Not covered here: a real SMS to the owner's phone (no provider calls in worker sessions), and capturing a photo with a real phone camera (M, lead's device run).
