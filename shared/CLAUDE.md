# shared/

pnpm workspace packages: `@todayz/tokens`, `ui`, `api-client` (generated), `i18n`, `telemetry`, `config`. Becomes the versioned `todayz-shared` package after the repo split.

Read first: the root `CLAUDE.md`, `docs/plan/README.md`, `docs/plan/01-product-rules.md`, then 02-architecture.md §1, §4.1; 05-observability.md (telemetry); design/source/tokens.json.

## Run

- `pnpm --filter './shared/*' test`

## Rules for this folder

- `api-client/src/gen` and `api-client/src/mocks/handlers.gen.ts` are generated by `make gen`
  (`mk/25-contract.mk`: Redocly bundle, orval, `scripts/msw.mjs`) and git-ignored. To change the
  client, change the contract in `backend/api/paths/<domain>.yaml` (see `backend/api/README.md`) and
  run `make gen`; never edit the bundle or anything under `src/gen`.
- Apps import `@todayz/api-client` (configure, ApiError, request), `@todayz/api-client/gen/<domain>/<domain>`
  (one function per operationId, typed by `gen/model`), `…/<domain>.zod` (Zod schemas) and
  `@todayz/api-client/mocks` (MSW `handlers` from the contract examples, `problemResponse`). Every
  call goes through `request()`: a non-2xx answer is thrown as `ApiError` with the problem `code`.
- `ui` is owned by W1-02 in Wave 1 and by the lead afterwards (D-84): ask the lead for component changes.
- Each i18n area file is owned by the WP that owns the screen area.
- Product events: `telemetry/events/<domain>.yaml`, owned by the domain's WP.
- No raw hex outside `tokens`.

W1-07: `telemetry` is complete: web-vitals, long tasks, route timing (`routeStart`/`routeReady`), traced
fetch (`traceparent`), Sentry seam (no SDK dependency; staging and production with a DSN only), and a typed
event emitter generated from `telemetry/events/*.yaml` (`src/gen`, git-ignored). Nothing is sent locally.

W1-08: `auth` (`@todayz/auth`) is the shared session core and sign-in UI for the three apps: in-memory token with cookie refresh (cross-tab race per D-105), `PhoneOtpFlow` (Turnstile, OTP, resend), offline banner, error boundary, update controller and toast (held while a sale or checkout is open), and the build-time site-key check (`@todayz/auth/build`) plus `scripts/precache-check.mjs`. Tests: `mk/46-auth.mk`.

W1-08 review round: `request()` sends the cookie (`credentials: 'include'`) to every `/v1/auth/*` route; `/v1/auth/logout-all` is a cookie route like refresh and logout (no bearer, never retried by `authFetch`). The session keeps two non-secret hints in localStorage (`todayz.hasSession.<app>`, `todayz.logoutPending.<app>`), stays `unknown` and retries when the first load cannot reach the API, ignores late cross-tab messages by stamp, and exposes `onUserChange` (apps clear their query cache; admin also clears the second-factor flag). `authFetch` refreshes and retries only a plain `unauthorized` 401 (or one without a body); other 401 codes such as `otp_expired` go to the caller. `session.signOutEverywhere()` refreshes once and retries logout-all once on a 401, then throws and leaves this tab signed in. `safeNext` / `validateNextSearch` (`@todayz/auth`) are the one `?next=` check for all three apps. `@todayz/auth/build` allows the dev Turnstile key and API URL only in modes development, test and e2e.

D-275: `PhoneOtpFlow` asks `GET /v1/auth/config` which path to use. On `firebase` it loads the Firebase SDK in its own chunk (`firebase-sdk.ts`, `import()` from `firebase.ts`, about 28 KB gzip, never in the initial bundle), signs in by phone with an invisible reCAPTCHA (in-memory persistence, signed out of Firebase right after), and swaps the ID token at `POST /v1/auth/firebase/verify`; a `409 sign_in_method_changed` restarts the flow on the other path. `FIREBASE_AUTH_EMULATOR_URL` from the config points the SDK at the mocks server locally. `/v1/auth/config` and `/v1/auth/firebase/verify` are in `request()`'s no-bearer list with the other sign-in routes. Firebase errors are reduced to a kind (`firebaseErrorKind`); the SDK's message is never shown or logged.

W1-08 second review round: `signOut()` forgets the token first (clears it, stamps and broadcasts), then calls logout with a 10 s abort (`logoutTimeoutMs`); a refresh asked for during or queued behind a sign-out returns false. The token life comes from the JWT `exp - iat` applied to the local receive time (no `Date` header). `lastUserId` survives sign-out, so a different person signing in after a sign-out or final 401 fires `onUserChange`. A missing or throwing store counts as "unknown", so the cookie is still tried. A signed-in tab retries a failed refresh with backoff, capped at 5. `SessionPending` is what every gate shows while the session is `unknown`: skeleton, and when offline the notice plus a "Try again" button (`session.start()`).
